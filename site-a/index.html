WebMCP is not enabled in this browser

Airlock registers its tools through document.modelContext, which Chrome only exposes behind a flag. Until it is on, no tool exists and nothing on this page can run.
  1. Open chrome://flags/#enable-webmcp-testing — Chrome 149 or later
  2. Set it to Enabled, then relaunch Chrome
  3. Come back to this page and reload

Drive it with a real agent

Airlock registers plain WebMCP tools, so any agent can operate it. The quickest way to see that is Google's own Model Context Tool Inspector extension, whose agent chat runs gemini-3-flash-preview. Ask it in your own words:

“How much does our high lifetime value audience overlap with Meridian's sports fans?”

Before approval it will tell you no such tool exists, because none does. Ask it to export Meridian's records and it will be refused. Nothing here is scripted for it.

Bring your own model not configured

Airlock has no backend and ships no API key. It registers plain WebMCP tools, and any agent can drive them.

Chrome's built-in agent needs nothing here — it runs gemini-3-flash-preview and finds these tools by itself. If you would rather watch a model reason over them in this panel, paste your own Gemini API key below.

Where your key goes
It is kept in this browser's local storage and sent only to Google's API from this page. Airlock has no server, so it never reaches us, and it is never written to the audit trail. Remove it any time.

What the model is given

Whatever getTools() returns at that moment, converted to function declarations — nothing more. Before approval, estimate_overlap is not in that list, so the model is never told it exists. That is the boundary, and it does not depend on the model behaving well.
